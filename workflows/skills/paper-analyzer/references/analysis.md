# 分析模式与证据约定

- Quick：问题、贡献、核心方法、主要发现与局限；明确选读范围。
- Deep：研究问题、设计逻辑、证据链、关键推导或方法、材料与数据、结果与适用边界。公式、实验或代码仅在论文实际包含时分析。
- Critical：辨别假设、偏差、论证缺口与复现条件，不将分析者风险猜测写成已观察到的失败。
- Comparative：分别记录阅读范围，再比较问题、研究设计、证据与结论；条件不同不直接排名。
- Implementation：用户需要时核对真实代码、数据、协议或研究材料，区分论文描述与实际行为。没有可执行代码不代表不能复核研究。

每条结果区分 paper_fact / reasoned_interpretation / ai_suggestion；来源绑定 source_id、PDF SHA256、版本和 PDF 页码。无 PDF 时按实际材料定位，不伪造 PDF 信息。当前结构化 JSON 验证器以 PDF 页为基础，其他来源需独立审阅，不能伪装成已通过同一路径。

Schema 只验证结构；validate-analysis 检查引文位置。两者均不独立证明语义或结论正确。缓存包含身份、PDF Hash、Parser Version、问题、模式、页码与分析配置；改变模型或分析约定时应更新配置以避免混用。
